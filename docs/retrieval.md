# CyberRAG Retrieval Architecture & Subsystem Guide

## Overview

The CyberRAG retrieval subsystem implements a **Hybrid Retrieval Subsystem** combining:
1. **PostgreSQL**: System of record for authoritative vulnerability data, handling structured queries, filters, and exact CVE/identifier matching.
2. **Qdrant**: Vector index performing dense semantic similarity search over vulnerability text embeddings generated by `BAAI/bge-small-en-v1.5`.
3. **RRF Fusion**: Reciprocal Rank Fusion algorithm merging lexical and semantic result sets into a unified, normalized relevance ranking with exact CVE overrides.

> **Key Architectural Guarantees**:
> - **PostgreSQL = System of Truth**: Qdrant stores vectors with minimal payload (`postgres_id`, `source`, `vulnerability_id`, `cve`, `vendor`, `product`). Authoritative vulnerability details are hydrated directly from PostgreSQL.
> - **Qdrant = Derived Index**: Qdrant can be rebuilt at any time by running the incremental embedding worker.
> - **Relevance vs Risk**: Retrieval evaluates query evidence relevance. Risk scoring/prioritization is delegated to the downstream Risk Assessment Agent.

## 1. Vector Configuration & Embedding Workflow

- **Embedding Model**: `BAAI/bge-small-en-v1.5`
- **Vector Dimension**: `384`
- **Qdrant Collection**: `vulnerabilities`
- **Distance Metric**: `Cosine`
- **Deterministic Text Format**:
  ```text
  Vendor: <vendor>
  Product: <product>
  Title: <title>
  Description: <description>
  Affected versions: <versions>
  Patched versions: <versions>
  ```

---

## 2. Idempotency & Embedding Worker

The embedding pipeline is incremental and idempotent:
- Qdrant Point ID is deterministically set to `str(vulnerability.id)` (the PostgreSQL UUID).
- Ingestion computes a `content_hash`. If a vulnerability record's data changes, its status resets to `pending`.
- Rerunning the worker never creates duplicate vectors.

### Running the Embedding Worker

To run the background batch worker from the `backend/` directory:

```bash
python -m indexing.embedding_worker
```

Configuration options inside `backend/.env`:
- `EMBEDDING_MODEL=BAAI/bge-small-en-v1.5`
- `QDRANT_COLLECTION=vulnerabilities`

## 3. Python Service Interface (For LangGraph Agents)

Future LangGraph agent nodes can invoke the retrieval subsystem directly in Python without network HTTP overhead:

```python
from app.database.postgres import SessionLocal
from app.retrieval.service import VulnerabilityRetriever

db = SessionLocal()
retriever = VulnerabilityRetriever(db)

# Basic search
results = retriever.retrieve(query="Apache Log4j remote code execution", limit=10)

# Filtered search
results = retriever.retrieve(
    query="privilege escalation",
    vendor="Microsoft",
    product="Windows",
    kev=True,
    limit=5,
)

for r in results:
    print(f"ID: {r.vulnerability_id} | CVE: {r.cve} | Score: {r.final_score}")
    print(f"Title: {r.title}")
    print(f"Sources: {r.retrieval_sources}")
```

## 4. HTTP API Endpoint

### Endpoint Signature

`GET /api/v1/search` or `POST /api/v1/search`

#### Request Parameters (GET Query Parameters)

| Parameter | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `q` | `string` | Yes | Search query or exact CVE ID |
| `vendor` | `string` | No | Filter by vendor |
| `product` | `string` | No | Filter by product |
| `severity` | `float` | No | Minimum CVSS severity threshold |
| `source` | `string` | No | Source filter (`NVD`, `CISA`, `GITHUB`, `OSV`) |
| `kev` | `boolean` | No | Filter CISA Known Exploited Vulnerabilities |
| `exploit_available` | `boolean` | No | Filter vulnerabilities with public exploit availability |
| `limit` | `int` | No | Max results to return (default: `20`) |

### Example cURL Request

```bash
curl -X GET "http://localhost:8000/api/v1/search?q=remote+code+execution&vendor=Microsoft&limit=5"
```

## 5. Failure & Fallback Handling

- **Qdrant Unavailability**: If Qdrant is offline or unreachable, `VulnerabilityRetriever` logs a warning and falls back to PostgreSQL lexical/structured results without crashing.
- **PostgreSQL Unavailability**: Returns a structured HTTP 500 error log.
- **Batch Worker Resilience**: Individual item failures are caught and marked as `failed` in PostgreSQL without halting batch execution.
